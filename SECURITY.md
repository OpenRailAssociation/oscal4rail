# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in OSCAL4Rail, please report it
privately so we can address it before it is disclosed publicly.

**Preferred channel:** Use GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
for this repository:

1. Go to the **Security** tab of this repository.
2. Select **Report a vulnerability**.
3. Describe the issue, affected versions, and reproduction steps.

Please do **not** open a public issue for security problems.

## What to Include

- A description of the vulnerability and its potential impact.
- Steps to reproduce or a proof of concept.
- Affected files, versions, or configurations.

## Response

The maintainers will acknowledge your report, assess the issue, and keep you
informed about the remediation. Once a fix is available, we will coordinate
disclosure with you.

## Scope

This policy covers the OSCAL4Rail framework, schemas, and tooling in this
repository. The NIST OSCAL base schemas (`schemas/nist/`) are maintained
upstream by NIST; vulnerabilities in the OSCAL standard itself should be
reported to the [NIST OSCAL project](https://github.com/usnistgov/OSCAL).
